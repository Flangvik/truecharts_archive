# Truecharts App Update Guide for AI Models

## Purpose

This document provides step-by-step instructions for AI models to update applications in this Truecharts archive repository. The official Truecharts repo has been deprecated and the previous maintainer has stopped updates. This guide enables automated or AI-assisted updates so TrueNAS SCALE users can keep their apps (chronos, jackett, ombi, overseerr, plex, qbittorrent, radarr, sickchill, syncthing, tailscale, tautulli, etc.) current.

## Repository Structure

```
truecharts_archive/
├── stable/          # Production-ready apps (plex, radarr, qbittorrent, etc.)
├── incubator/       # Beta/experimental apps
├── system/          # System charts (cert-manager, prometheus, etc.)
├── premium/         # Premium apps
└── catalog.json     # Catalog index (may need regeneration)
```

Each app has this structure:

```
stable/{app-name}/
├── item.yaml              # App metadata (icon, categories)
├── app_versions.json      # Version metadata (auto-generated by build)
└── {version}/             # e.g., 18.3.7, 9.0.9
    ├── Chart.yaml         # Chart version, appVersion, dependencies
    ├── ix_values.yaml     # Default values - IMAGE CONFIG HERE
    ├── values.yaml        # Usually empty
    ├── charts/
    │   └── common-23.0.10.tgz   # Common dependency (do not modify)
    ├── templates/
    └── ...
```

## Key Files to Modify When Updating

| File | What to Update |
|------|----------------|
| `Chart.yaml` | `appVersion` (upstream app version), `version` (chart version, increment patch) |
| `ix_values.yaml` | `image.tag` (use format `VERSION@sha256:DIGEST` when possible) |

## Update Procedure

### Step 1: Identify the App and Current State

- Locate the app in `truecharts_archive/stable/`, `incubator/`, or `system/`
- Find the **latest version folder** (highest semantic version number)
- Read `Chart.yaml` for `appVersion` and `sources`
- Read `ix_values.yaml` for `image.repository` and `image.tag`

**Example (plex):**
- Path: `truecharts_archive/stable/plex/18.3.7/`
- Chart.yaml: `appVersion: 1.42.2.10156`, `version: 18.3.7`
- ix_values.yaml: `repository: "ghcr.io/home-operations/plex"`, `tag: "1.42.2.10156@sha256:9ad8a3506e1d8ebda873a668603c1a2c10e6887969564561be669efd65ae8871"`

### Step 2: Find the Upstream Image Source

Image sources are in `Chart.yaml` under `sources` and in `ix_values.yaml` under `image.repository`. Common registries:

- **Docker Hub:** `docker.io/library/ubuntu` or `ubuntu`
- **GitHub Container Registry:** `ghcr.io/owner/image`
- **OCI/TrueForge:** `oci.trueforge.org/containerforge/appname`

Check the upstream project (GitHub releases, Docker Hub tags) for the latest version.

### Step 3: Get the Image Digest (Recommended for Security)

Digest-pinned tags ensure reproducible builds. Use one of:

```bash
# Using Docker (if available)
docker buildx imagetools inspect IMAGE:TAG

# Using crane (from go-containerregistry)
crane digest IMAGE:TAG

# Using skopeo
skopeo inspect docker://IMAGE:TAG --format '{{.Digest}}'
```

The output format is `sha256:xxxxxxxx`. The full tag becomes: `VERSION@sha256:xxxxxxxx`

**Note:** Some charts use tags without digest (e.g., `tag: 5.1.4` or `tag: rolling`). Prefer adding digest when possible.

### Step 4: Create the New Version

1. **Copy** the latest version folder to a new folder with the **new chart version**
   - Chart version format: `MAJOR.MINOR.PATCH` (e.g., 18.3.6 -> 18.3.7)
   - Increment PATCH when updating only the app image; consider MINOR for config changes

2. **Edit the new folder's `Chart.yaml`:**
   - `appVersion`: Set to the new upstream app version (e.g., `1.42.3.xxxxx`)
   - `version`: Set to the new chart version (e.g., `18.3.8`)

3. **Edit the new folder's `ix_values.yaml`:**
   - `image.tag`: Update to `NEW_VERSION@sha256:DIGEST` or `NEW_VERSION` if no digest

4. **Preserve all other files** - templates, common.tgz, questions.yaml, etc. typically do not need changes for image-only updates.

### Step 5: app_versions.json and catalog.json

- **app_versions.json** – Required for TrueNAS Apps UI. After adding new version folders, run:
  ```bash
  python3 build_app_versions.py                    # Update all apps
  python3 build_app_versions.py stable/jackett     # Update specific app(s)
  python3 build_app_versions.py --dry-run          # Preview without writing
  ```
  The script adds entries for any version directory that exists on disk but is missing from the JSON. A GitHub Action (`.github/workflows/build-catalog.yaml`) runs this automatically on push to `main` when chart paths change.
- **catalog.json** – The `charts` key for stable is empty in this repo; the catalog may be built by an external process. If TrueNAS uses a custom catalog URL pointing to this repo, you may need to research the expected catalog format.

### Step 6: Common Chart Dependency

All charts depend on `common` from `oci://tccr.io/truecharts`. The `.tgz` file is **bundled** in each version's `charts/` folder. Do **not** remove or replace it unless you have a new common chart source. The bundled `common-23.0.10.tgz` should continue to work.

## Checklist for Each Update

- [ ] Identified current version and upstream source
- [ ] Verified new upstream version exists
- [ ] Retrieved image digest (if using digest pinning)
- [ ] Created new version folder (copied from previous)
- [ ] Updated Chart.yaml (appVersion, version)
- [ ] Updated ix_values.yaml (image.tag)
- [ ] Left common.tgz, templates, questions.yaml unchanged
- [ ] Ran `build_app_versions.py` to update app_versions.json (or let CI do it on push)
- [ ] Tested chart with `helm template` or `helm lint` if Helm is available

## Version Numbering Conventions

- **Chart version** (e.g., 18.3.7): Increment PATCH for app image updates. The first number often aligns with a major chart structure iteration.
- **appVersion** (e.g., 1.42.2.10156): Must match the upstream application version exactly.
- **human_version** (in app_versions.json): Format `appVersion_chartVersion` (e.g., `1.42.2.10156_18.3.7`)

## Troubleshooting

- **Image pull errors:** Verify the image exists at the repository and tag. Check Docker Hub / GHCR for rate limits or authentication.
- **Chart fails to render:** Ensure `common-23.0.10.tgz` is present in `charts/`. Do not change the dependency in Chart.yaml unless you have a replacement for `oci://tccr.io/truecharts`.
- **Multiple images:** Some apps (e.g., radarr with exportarr) have secondary images. Update each `*Image` / `*image` block in ix_values.yaml as needed.

## Summary

To update an app: copy the latest version folder, bump the chart version and appVersion, update the image tag in ix_values.yaml (preferably with digest), run `build_app_versions.py` to update app_versions.json, and leave the rest unchanged. This keeps the Truecharts archive functional for TrueNAS SCALE users.

## Automation

| Script | Purpose |
|--------|---------|
| `build_app_versions.py` | Adds new version entries to app_versions.json for version dirs on disk |
| `cleanup_versions.py` | Prunes old versions (keeps N latest) and updates app_versions.json |
| `.github/workflows/build-catalog.yaml` | Runs build_app_versions.py on push; commits and pushes JSON updates |
